# Site audit: June 2026 (Wave 1)

**Audience: the maintainer.** A cross-cutting static audit of the NetSec
site run on 2 June 2026 across all pages and the three locales, covering
six dimensions: accessibility, writing voice, link integrity, dead code,
responsive layout, and SEO metadata. Each dimension was swept
independently, and every high-severity finding was adversarially
re-verified against the repository before being acted on.

This is a point-in-time snapshot, not a living document. Dispositions
below record what was fixed, what was dismissed as a false positive,
and what was deferred.

## Voice & style

No violations in current prose. Every em dash and semicolon detected sits
in CSS, inline JavaScript, encoded entities, or aria-hidden regions, not
in visible copy. The house voice rules (CLAUDE.md sections 1, 6, 7) hold
across all three locales.

## SEO / metadata

The English ESSC page (`essc-2026.html`) declared only `en` and
`x-default` hreflang alternates while its FR and DE variants carried the
full set. **Fixed in #455**: added the `fr` and `de` alternates and
dropped the stale "variants will land in the next PR" comment.

Everything else is clean: `inject-seo.py` drives complete title,
description, canonical, Open Graph, Twitter Card, and JSON-LD across all
managed pages.

## Link integrity

All internal links and fragment anchors resolve (51 unique internal
destinations, plus the JavaScript-generated member-card ids handled by
the scroll handler). No dangling anchors.

The only finding is the Formspree privacy-policy link
(`https://formspree.io/legal/privacy-policy`) on `privacy.html` and its
two locale variants, listed as L3 in `docs/launch-qa-2026.md`. Current
status: the URL responds via a 301 redirect rather than a direct 200, so
it works for visitors, and the link-checker was already configured to
accept it. **Left unchanged and flagged for a human:** a privacy-policy
link on a legal page should only be repointed once someone confirms the
canonical Formspree URL (the trailing-slash form looks correct but was
not verified here, and guessing on a legal page is the wrong call). This
remains tracked as launch-QA L3.

## Dead code

Nine asset directories were leftovers from the original Mobirise build
with zero references anywhere in the repository: `assets/bootstrap`,
`assets/mobirise`, `assets/web`, `assets/formoid`,
`assets/mbr-switch-arrow`, `assets/theme`, `assets/ytplayer`,
`assets/dropdown`, `assets/smoothscroll` (about 940K). **Removed in
#454**, opened as a review-me PR rather than auto-merged because bulk
deletions deserve a human glance.

Two print-only CSS classes are confirmed unused but **deferred**:
`.faq-item` (shares a rule with the used `.faq-section`, so a trivial
trim) and `.pk-colour-swatch` (a print affordance for press-kit colour
chips that was styled but never wired to any markup). The second looks
like a latent feature rather than accidental cruft, so it is left for a
human call rather than removed unattended.

## Accessibility (WCAG 2.2 AA)

No real violations after verification. The two flagged patterns are both
false positives:

- **Empty `h2.ue-headline`** on the home page (all three locales). The
  parent `.upcoming-event` section carries `hidden`, and the JavaScript
  fills the heading before unhiding the section, so an empty heading is
  never exposed to assistive technology or to non-JS users (the section
  stays `display:none`). No change.
- **Empty `alt` on the member-card template image** (all three locales).
  This is a `<template>` placeholder with no `src`. The renderer
  populates both `src` and the accessible context (the member name
  heading) at runtime. Low risk, documented, no change.

Otherwise: alt text complete, no heading-order jumps, correct landmarks
and roles, icon buttons carry `aria-label`, skip-links resolve, and
`lang` attributes are correct throughout.

## Responsive layout

One finding dismissed: the About-page Gantt chart is already wrapped in
`.gantt-wrap { overflow-x: auto }`, so it does not overflow narrow
viewports (it scrolls).

The visual rendering pass (issue #457) reviewed the remaining four
candidates against the CSS cascade and rendered breakpoints. Outcome:

- **Search-overlay close button: fixed.** `.search-close` was a 32px
  square, below the 44px touch-target guidance. Bumped to 44px (the
  icon stays 16px, centred). This was the one confirmed defect.
- **WG member grid: cleared.** `repeat(auto-fill, minmax(150px, 1fr))`
  resolves to three comfortable columns at 540px (a 64px avatar plus
  name, role, and affiliation sit within ~160px), not a cramped reflow.
- **Add-to-calendar menu width: cleared.** `.event-atc-menu` is
  reparented to `<body>` and pinned with `position: fixed` from
  `getBoundingClientRect`, so its 200px minimum width fits within a
  375px viewport without overflow.
- **ESSC quick-facts padding: cleared.** `.essc-quickfacts` collapses to
  a single column at ≤480px (the later cascade rule wins), and the
  `18px 22px` padding reads comfortably on a phone.

## Method and limits

Six parallel static auditors (one per dimension) swept the repository
with grep and file reads. High-severity findings were re-verified by
independent agents instructed to refute them. Static analysis catches
structure and references, not live rendering: the responsive and
visual-contrast questions are explicitly handed to a rendering pass. No
external network checks were made, so external-URL liveness rests on the
launch-QA record and the link-checker.
