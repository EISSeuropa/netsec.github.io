# Publishing news

NetSec news lives in one place, `data/news.json`, and feeds three surfaces:

- the **home page** "Latest News" block (the most recent items, capped at 3,
  decaying off after 18 months, each shown as a one-line summary), rendered
  by `assets/js/home-news.js`;
- the **`/news` archive** (the full chronological list, all three locales),
  rendered by the same script's `renderNewsArchive`;
- the **RSS feed** at `/news.xml`, generated by `scripts/build-news-rss.py`.

## Adding an item

There are two ways: the issue form, or a PR that edits the JSON.

### The News item form

Open a new issue and pick **News item**
([`.github/ISSUE_TEMPLATE/news.yml`](../.github/ISSUE_TEMPLATE/news.yml)).
It is in English. Only the headline (or the issue title) and the summary are
needed. The form applies no label, so filing it publishes nothing.

| Field | Goes to |
| --- | --- |
| Site | NetSec: nothing extra. Joint: `"site": "joint"`. EISS: the run stops, file it in the EISS repository |
| Headline | `title.en` (blank: the issue title, minus a leading `news:`) |
| Summary | `summary.en`, cut to 300 characters |
| Body | `body.en` (blank: the summary) |
| Type | `type` (default `announcement`) |
| Working Group | `wg` |
| Link | `cta`: an existing page, never a new one, shown as "Read more →" in each locale and at the end of the social posts. A page on this site links its `.fr.html` and `.de.html` pages when both exist. Blank: no button, and the posts link to the home page news |
| Publication date | `pubDate` at 12:00 Paris time, and `displayDate` in each locale (blank: the day the label is applied) |
| On the home page until | `homeUntil` at 23:59 Paris time |
| Collaborator page | `"collaborator": "eiss"` |
| Include in the newsletter | `"newsletter": true` |
| Do not post to LinkedIn and Bluesky | `"social": "skip"` |

The `Publish news from issue` workflow
([`.github/workflows/news-publish.yml`](../.github/workflows/news-publish.yml))
runs [`scripts/news-from-issue.py`](../scripts/news-from-issue.py), which
adds the item to the top of `data/news.json` and asks the Claude API for the
French and German title, summary and body. The workflow then rebuilds
`news.xml` and opens a PR with `Closes #<issue>`. It starts in two ways:

- A publisher files the form. The run starts as soon as the issue is opened.
- A publisher applies the **`news`** label to a form issue someone else filed.

The PR waits for the maintainer. Merging it approves the machine translations
(CLAUDE.md §1), publishes the item, and starts the gated social posts. To
change the item first, edit the entry on the PR's branch and rerun
`python3 scripts/build-news-rss.py`. To drop it, close the PR and the issue.
When the translation did not run (no `ANTHROPIC_API_KEY` secret, or the call
failed), the PR body says so, and the FR and DE text can be added on its
branch before merging.

**Publishers.** The GitHub accounts in the repository variable
`NEWS_PUBLISHERS`, separated by commas, semicolons or spaces, the same as on
the EISS site. A form issue opened by anyone else waits, with no comment, until
a publisher applies the label. A label applied by anyone else gets a comment
saying nothing was published. With the variable unset, nobody can publish.

**Set-up (once, by the maintainer).** Create the `news` label, set
`NEWS_PUBLISHERS`, and add an `ANTHROPIC_API_KEY` repository secret for the
translation. The workflow opens its PR with `AUTOPR_TOKEN`, like the other
auto-PR workflows, so the required checks run on it.

**Tests.** `python3 -m pytest scripts/test-news-from-issue.py` runs without
network. It also fails when the form lists `None` or `n/a` in a dropdown,
which makes GitHub hide the form from the issue chooser.

### Editing the JSON

Prepend the item to `items` in `data/news.json`, bump `lastBuildDate`, then
run `python3 scripts/build-news-rss.py` and commit both files in one PR. The
`news-drift.yml` CI gate fails if `news.xml` does not match `news.json`.

Write the English first. FR and DE may be translated by hand or by machine,
and merging the PR approves them (CLAUDE.md §1). An item with only `en` keys still renders on the
FR and DE pages, which fall back to English until the translation lands.

The home page's fallback cards, shown without JavaScript and indexed by the
site search, are rewritten from `data/news.json` at every deploy by
`scripts/render-news-fallback.py`, so they need no hand editing.

A new item also becomes a candidate social post. The optional `social` field
below controls that, and [`social-publishing.md`](./social-publishing.md)
describes the rest.

## Schema (per item)

| field | required | notes |
| --- | --- | --- |
| `id` | yes | Stable slug. The archive anchors at `#news-<id>`. |
| `pubDate` | yes | ISO datetime. Drives sort order and decay, and the archive groups items under a year heading from it. |
| `title` | yes | `{en, fr?, de?}` |
| `body` | yes | `{en, fr?, de?}`. Shown in full in the archive and the RSS feed. |
| `summary` | no | `{en, fr?, de?}`, one sentence for the home card. Without it the card shows the body's first sentence. |
| `displayDate` | yes | `{en, fr?, de?}`, the date pill text. |
| `type` | no | A category pill beside the date: `event`, `publication`, `announcement` or `call`. These four are translated on the FR and DE pages. Any other word still renders, title-cased. A `call` also appears in the home page's Open calls tile. |
| `wg` | no | Working Group number, `1` to `4`, rendered as a WG-coloured pill such as `WG3`. |
| `homeUntil` | no | ISO datetime. After it the item leaves the home page but stays in the archive and the RSS feed. On a `call` it drives the countdown in the Open calls tile, and a call without it shows as a rolling call. |
| `cta` | no | `{href, external, i18n:{en, fr?, de?}}`, a "Read more" link. `href` may be a string or a per-locale map. |
| `social` | no | Bluesky and LinkedIn handling: omit it or set `"auto"` to offer the item for posting, `"skip"` to never post it, or `"thread:<slug>"` when a curated thread announces it instead. |
| `site` | no | `"joint"` for an item shared with EISS. The site ignores it. |
| `collaborator` | no | `"eiss"`: after a LinkedIn post, the posting run lists it for adding the EISS page as collaborator by hand. LinkedIn's API cannot do it. |
| `newsletter` | no | `true` puts `<category>newsletter</category>` on the item in `news.xml`, which the monthly newsletter reads. |
